# 局域网双人对战

## 如何使用

1. 把当前完整项目复制到另一台 Windows 电脑，两台电脑均需安装 Python 和 Tkinter。
2. 连接同一个家庭或教室网络。确认双方使用的网卡在 Windows 中属于可信的“专用网络”，并开启 Windows 防火墙。
3. 正常启动游戏，点击右侧分析面板底部的 **联机**。
4. 房主选择本地有线或 Wi-Fi 网卡，使用默认端口 `39741`，选择执红或执黑，并决定是否允许指导，然后点击 **创建房间**。
5. 首次创建时可能出现 Windows 管理员确认，用于添加受限的防火墙规则。拒绝确认或配置失败时不会开放房间。
6. 将房间显示的 IPv4 地址、端口和 16 位房间码告诉对手。对手点击 **联机**，选择自己的网卡，填写房主信息并点击 **加入房间**。房间码区分大小写。
7. 双方连接后开始下棋。自动视角默认己方在上：执红看到红方在上，执黑看到黑方在上；点击棋盘上方的“翻转棋盘”即可交换上下位置，再点一次恢复。双方独立调整，互不影响，也不改变执方或行棋轮次。

手动朝向在本次程序运行期间保留，悔棋、重开、切换执方或模式、推演及重连不会覆盖。重新启动后恢复自动。等待连接、断线、引擎思考或推演回放时仍可调整朝向；翻转只改变显示，不改变棋局。

“创造模式”只用于本地人机或双人棋局，联机及连接过程中不可使用；房间内不接受任意替换局面的消息。

关闭联机小窗口不会退出房间。点击右侧底部的“联机”可以再次打开房间信息与操作。

## 对局操作

- 新棋局：向对手申请重新开局，需要对方同意。
- 悔棋：申请撤回最后一个半回合，即双方合计的最后一步，需要对方同意。
- 求和、认输：在联机窗口操作。求和需对方同意，认输直接结束本局。
- 有申请等待回复时暂停落子。断线会清除待回复申请，旧申请不能在重连后生效。
- 断线后棋局暂停。加入方在原程序、原房间中点击“断线后重连”；房主保持房间开放并等待。棋盘和全部着法历史由房主重新同步。
- 房主退出或关闭程序会关闭房间。首版没有房主迁移，也没有退出程序后的对局恢复。
- 加入方退出程序会失去仅保存在内存中的重连身份。此时由房主退出并重新创建房间，再开始新局，避免新连接冒充原玩家。
- 一间房只有两名玩家，不支持第三人旁观。
- 局域网对战关闭 AI/API 代走和自动 AI 应手。允许指导时，可使用推荐、推演、威胁分析、棋谱参考及 API 评议；否则这些入口关闭。指导开关是双方约定，不能阻止使用软件之外的辅助工具。
- 切回“人机”或“双人”会提示退出联机房间，然后恢复本地游戏。

## 访问范围

生产代码只接受具有 RFC1918 私有 IPv4 地址的在线物理有线/Wi-Fi 网卡，校验真实网卡的子网掩码、专用网络类别与防火墙状态。拒绝公网 IPv4、IPv6、通配监听地址、回环、链路本地地址及其他网段。不会开启 UPnP、端口映射、广播发现或内网穿透。

创建房间时只监听选定网卡的确切 IPv4 地址。Windows 防火墙规则只允许该 Python 程序、指定网卡、指定本地地址、指定 TCP 端口及该网卡所在子网，且仅在专用网络下生效，禁止边缘遍历。规则名称以 `XiangqiCoach-LAN-` 开头。关闭房间会关闭监听套接字；受限防火墙规则保留供下次使用，不会自动删除其他应用的规则。

服务端另行检查每个连接的来源地址，限制并发握手、连接尝试和消息频率。网卡、网络类别或防火墙状态变化时停止房间。若要清理本软件的残留规则，可在 Windows Defender 防火墙“高级设置 → 入站规则”中删除名为 `Xiangqi Coach LAN (private subnet only)` 的规则。

“同一路由器”不等于“同一子网”。访客 Wi-Fi、无线隔离或不同 VLAN 可能导致无法连接。VPN、代理或人为配置的源地址转换可能让远端流量看起来来自本地地址，软件不能仅凭来源 IP 识别所有此类情形；不要自行配置公网端口映射、代理或内网穿透。

## 数据和协议

房主保存权威棋局，客户端发送走棋请求，房主验证身份、执方、轮次、对局编号、递增修订号和合法着法后才广播结果。客户端复核历史合法性以及 FEN 与历史的一致性。双方都不会直接接受对方任意替换棋盘。

通信使用有长度上限的 JSON，单帧不超过 64 KiB。随机房间码不在网络中直接传送，以挑战应答校验身份；后续消息使用方向独立的 HMAC 和递增序号进行完整性与重放检查。消息经过身份校验，但未加密，局域网观察者仍可能看到棋局数据。不传送 API Key、引擎路径或用户文件。

完整长将、长捉和重复局面裁判仍未实现，沿用现有合法性与终局判断，并设置 2048 个半回合的单局资源上限。

## 代码位置

- `lan_network.py`：网卡发现、子网与网络类别检查、防火墙配置。
- `lan_protocol.py`：JSON封包、挑战签名、会话完整性与快照校验。
- `lan_server.py`：双人房间、权威棋局、协商及连接生命周期。
- `lan_client.py`：加入、心跳与重连。
- `lan_ui.py`：创建/加入窗口、棋局同步与联机交互。
- `app.py`：联机入口及原游戏流程的少量分支。

修改前的 `app.py` 备份位于 `data/backups/app_before_lan_20260921.py`。Pikafish、Px0、规则和棋谱库业务文件未重写。

## 2026-10-19：双方往返限制

双方分别用同一枚棋子，在各自固定两个位置连续往返两轮时，
若当前方还有其他基本合法走法，完成第二轮的最后一着将被拒绝，需变招。
当前方基本合法走法只有一着时允许重复；本规则不新增和棋或判负。
单方往返、吃子中断及其他形式循环不在此次限制范围内。

房主统一检查走法，双方也会校验历史；拒绝走法不会改变棋局和版本号。
悔棋按撤回后的历史判断，断线重连保留已有历史，新局重新计算。
协议版本已升为 2，两台电脑均须更新软件、退出旧房间后重新创建。
本机双实例测试使用回环 TCP，不代替两台实体电脑的联网验收。
