# BF-V8.4 稳定性修复记录

- 问题：Pikafish 无输出时伪超时可能永久阻塞；局面变化后旧 API 评议可能写回新局面；后台线程在窗口关闭后可能继续调用 Tk。
- 根因：引擎读取直接使用阻塞式 `stdout.readline()`；API 请求编号没有在所有局面和方案变化时统一失效；工作线程直接调用 `after()` 安排控件更新。
- 修改文件：`engine.py`、`app.py`、`tests/test_engine_timeout.py`、`tests/test_app_interactions.py`。
- 最小补丁：增加引擎标准输出读取线程和有界等待队列；超时后终止无响应进程；关闭引擎不再等待分析锁；增加 Tk 主线程结果队列；走棋、悔棋、新局、推演切换和候选切换时使旧 API 请求失效。
- 验证：`py_compile`通过；pytest 15项通过；静默假引擎在0.15秒限制后被终止；关闭流程不等待分析锁；真实 Pikafish 初始局面返回3个候选，首选为合法着；GUI启动冒烟通过。
