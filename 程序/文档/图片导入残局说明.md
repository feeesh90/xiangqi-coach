# 图片导入残局（本地免费版）

更新：2026-10-10。本机已安装依赖和三个识别模型，可以直接使用，无需 API 密钥或另行下载。

## 使用步骤

1. 关闭旧的软件窗口，双击项目中的 `run.bat` 重新启动。
2. 点棋盘上方的 **残局 → 图片导入残局**。
3. 点 **选择截图**，选择完整、清晰的 PNG/JPG/JPEG 象棋截图，再点 **本地识别**。
4. 对照左侧原图和右侧预览。识别有误时，在“点击时放置”中选棋子，点击右侧对应交叉点替换或补子；选择“清空”可删除误识别棋子。
5. 黄色格子需要检查。修正该格会解除标记，也可以核对后点 **确认标记格**。即使没有黄色标记，也应核对整盘，识别可能漏子。
6. 设置下方四项，点 **确认导入**。确认前不替换正在进行的正式棋局；原棋局若轮到 AI，仍可正常继续。

| 设置 | 含义 |
|---|---|
| 图片下方 | 截图下方是红方还是黑方。根据将帅位置尝试预选，判断有误时可修改 |
| 轮到谁走 | 残局当前轮到红方还是黑方，必须由你明确选择 |
| 我执 | 人机对弈中你执红方还是黑方 |
| 翻转棋盘 | 点一次切换预览的上下方向；旁边显示实际哪方在下 |

这些设置彼此独立。例如：截图红方在上，轮到黑方走，你执红方，显示仍可让红方在下。想让红方在上时，点击“翻转棋盘”直到旁边显示“黑方在下”。翻转只改变预览；“图片下方”仍用于解释原图，不要随预览一起修改。

导入后继续使用已有的 Pikafish/Px0、推荐、评分、主变化、推演、回放、预走、人工接管和悔棋。轮到 AI 且有合法着法时，AI 自动先行；将死或无合法走法时只显示终局，不安排无效 AI 搜索。

## 棋盘定位不准怎么办

点 **标四角 / 校正网格**，在左侧原图依次点击最外侧的四个交叉点：左上、右上、右下、左下。选的是交叉点/棋子中心，不是木质棋盘边框。检查绿色网格是否对齐，再点“本地识别”。

标四角或重新识别会清除上一次草稿，避免误导入旧结果。选择另一张图片、取消识别、关闭窗口都会使旧结果失效。

## 重置、换执方和联机

- **残局 → 重置当前残局**：回到刚导入的起点，清空之后的走棋历史。
- **新棋局** 或 **残局 → 恢复标准开局**：恢复通常的红方先走标准开局。
- 引擎设置中修改“玩家执方”：成功后重置当前起点，导入的残局会保留；切换失败保持原设置。
- 本地人机/双人切换保留残局起点；悔棋不能越过该起点。
- 第一版仅供本地练习。联机房间和建立连接期间不能导入；需先退出联机。原联机协议和标准开局保持。
- 大师棋谱库按标准开局的历史前缀查询，非标准残局不使用此开局参考；引擎对当前 FEN 的分析继续可用。

## 图片和内存

正常使用时，软件读取你选择的原文件，在内存里生成缩略图与识别草稿，**不上传图片，不另存图片、不生成临时图片、不把图片写入棋谱数据库**。原文件不会被修改或删除。关闭预览或导入成功后清理图片引用；识别完成、取消或超时后，识别子进程退出，模型内存由系统回收。主程序的内存分配器可能保留少量已分配内存，数值不一定立刻回到打开前。

识图无需网络。首次安装/修复识别环境需要下载免费依赖和模型；原有可选文字 API 仍受你原来的 API 设置控制，它不参与这次图片识别。

本机样本实测：识别子进程峰值约 **140–150 MiB**，主界面另占约 **54–100 MiB**。它们不包括独立运行的 Pikafish/Px0 内存。更大的原图可能占用更多内存。十次连续实际导入后，全部识别进程已退出。

三个模型合计约 **27.9 MiB**，隔离的识别环境约 **241.1 MiB**，两者合计约 **269 MiB** 磁盘空间。模型文件体积与运行内存不是同一个数值。

开发测试单独保存了标注截图与结果，位于 `data/endgame_verification/`，是验收材料；正常用户导入不会向这里写文件。

## 另一台电脑的安装

保留项目内 `models/board_recognition/` 的模型和许可文件。在另一台电脑安装普通的 64 位 Python（本次已验证 3.14.7，安装脚本要求 3.12 或更高），双击 **安装图片识别.bat**。脚本建立项目内 `.recognition-venv/`、安装固定版本依赖、校验模型、补齐缺失模型，成功后重新启动 `run.bat`。

无需付费账户或显卡。虚拟环境不能直接当作可移植安装包，复制项目后应在目标电脑重新运行安装脚本。缺依赖/模型、损坏图片或识别失败时，原棋局与双引擎功能仍可使用。

## 已验证范围与限制

已验证本软件木色棋盘的红上/红下截图、宋体/楷体字形，以及公开资料中 Chinese Chess Endgame 的金色棋盘截图；外部截图自动定位、四角校正及缩小 JPEG 均通过逐格对照。没有验证所有象棋网页、皮肤或手机软件。

本软件 10 张标注截图中，9 张整盘正确、899/900 格正确；其中 8 张残局均正确。一张标准开局截图的黑车错格被标为待确认。外部软件截图另外核对，完整 90 格正确。这是小规模课程项目验证，不能代表任意图片的准确率。

第一版不保证实体棋盘照片、镜像、严重透视、缺角/遮挡、模糊字、所有棋子皮肤可识别。支持文件不超过 20 MiB、像素数不超过 1600 万、短边至少 100 像素；实际应使用棋子文字能清楚看见的完整截图。

导入会检查将帅数量、棋子上限、九宫及士象兵卒位置、将帅照面与非行棋方被将军等静态问题，但不验证该局面能否从开局逐步到达，也不新增完整长将、长捉和重复局面裁判。

## 文件与技术入口

| 文件 | 职责 |
|---|---|
| `app.py`、`lan_ui.py` | 本地入口、自定义起点、旧任务失效、棋谱查询保护、联机起点恢复 |
| `endgame_ui.py` | 选图、四角校正、预览纠错、四项设置和确认 |
| `position_import.py` | 独立草稿、方向归一化、静态校验、FEN |
| `board_recognizer.py` | CPU ONNX 检测、棋子分类、文字核对、颜色识别 |
| `recognition_process.py`、`recognition_worker.py` | 可取消、30 秒超时、有界 JSON 通信的一次性识别进程 |
| `requirements-recognition.txt`、`scripts/setup_recognition.*`、`安装图片识别.bat` | 隔离安装与模型校验 |
| `models/board_recognition/manifest.json` | 固定模型来源、文件大小、SHA-256 和许可记录 |

规则、引擎、API 与棋谱库模块没有为识图重写。具体测试结果见 `data/endgame_verification/验证说明.md`。
